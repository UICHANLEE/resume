# Prototype Instructions

Run the local server yourself and open the preview in the in-app browser. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

The dedicated AI Engineer resume must remain an actual one-page A4 resume, not a cover letter or portfolio narrative. Keep it concise, evidence-led, print-ready, and limited to experience, quantified outcomes, projects, skills, education, credentials, and intellectual property.

When the user provides or collects job postings, treat the list as an implementation request. For every posting, create an English company endpoint, write a tailored resume and cover-letter draft with clear Problem/Action/Result evidence, verify every route locally and in production, and push the completed changes. Do not stop at ranking, fit analysis, or recommendations unless the user explicitly asks for analysis only.
